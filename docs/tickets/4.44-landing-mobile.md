# 4.44 — Landing page : affichage mobile

> Énoncé reçu le 25/08/2026, versionné ici. Périmètre : la landing publique
> (nodaq.fr) uniquement — pas l'app.

## Pourquoi

Constat fondateur : la landing ne s'affiche pas correctement sur mobile.
Or la cible (artisans TPE/PME) découvrira nodaq très majoritairement sur
téléphone. **Le mobile est le cas nominal de la landing, pas une
adaptation.** Une landing cassée sur mobile = des clics publicitaires payés
pour rien.

Critère maître : chaque section doit passer le test des 3 secondes sur un
écran de 360×800 (Android d'entrée de gamme).

## Ce que l'audit a trouvé (Playwright, 360×800 / 390×844 / 414×896)

**Une seule cause de casse**, présente sur les trois viewports : la rangée
des dix liens produit du footer (`.footer__legal-links`) était un flex sans
repli — elle débordait de ~240 px (scrollWidth 574-601 pour 360-414 px
d'écran) et rendait les derniers liens inatteignables, le `overflow-x:
hidden` du body masquant le symptôme sans le corriger. Tout le reste était
déjà mobile-first : une colonne sous 640 px, corps 16 px, champ e-mail
16 px (pas de zoom iOS), images lazy en WebP, vidéo du hero coupée sous
640 px (poster seul), viewport meta en place, aucune librairie JS.

## Ce qui a été livré

- **La cause corrigée** : `flex-wrap: wrap` sur les deux rangées du footer.
  Zéro scroll horizontal sur les 7 pages types × 3 viewports (21/21).
- **CTA collant** « Essai gratuit 14 jours » : seul élément fixe de la
  page, apparaît après le premier écran de scroll, disparaît quand la
  section d'inscription est visible, cible ≥ 44 px pleine largeur,
  safe-area, masqué ≥ 1024 px. Jamais de popup.
- `text-wrap: balance` sur les titres.
- **Le hero tient dans le premier écran** en 360×800 : promesse + un seul
  CTA visibles sans scroll (vérifié en capture).
- **Ordre d'empilement des tarifs** : Fondateurs, puis Solo, puis Équipe —
  déjà l'ordre du DOM de `/tarifs`, vérifié en une colonne mobile.
- **Script `verifie-mobile.mjs`** versionné à côté des générateurs : le
  test automatisé `scrollWidth <= innerWidth` sur les 3 viewports, à
  passer avant chaque déploiement (la landing n'est pas construite par la
  CI — la porte est manuelle, comme la validation du contenu).
- **Mesures** (Lighthouse mobile, page servie en local) :
  Performance **100**, Accessibility **96**, LCP **1,5 s**, TBT 0 ms,
  CLS 0,004 — objectifs (≥ 90 / ≥ 95 / < 2,5 s) atteints.
